# Задачи: целостность спецификаций

Порядок не по «логике проекта», а по тому, что какой шаг ломает.

Раздел 1 обязателен для всего остального: пока валидатор принимает спеку без
семи разделов и с пустыми телами, **«зелёный прогон» не является аргументом ни за,
ни против** чего-либо — и правка 19 спек (раздел 4) будет нечем проверить.

Раздел 3 обязателен перед разделом 4: заполнять `## Implementation` в спеке, чей
предмет ещё не решён, — значит вписать путь, которого нет, и закрыть устаревшую
ссылку свежееутверждённой устаревшей ссылкой.

Разделы можно вести параллельно **только** с разными владельцами файлов.
`tools/validate_component_specs.py`, `tests/test_component_spec_validation.py`,
`openspec/specs/validation/`, `openspec/specs/architecture/`,
`openspec/specs/documentation/`, `openspec/specs/COMPONENTS.md` и
`.github/workflows/ci.yml` трогает один исполнитель одновременно: в них
пересекаются правки 1, 2, 5 и 6.

Все решения по предмету оформляются в задаче явно: `решение: <вариант>` +
`почему` + `согласовано: <дата, кто>`. Решение без этой записи считается
непринятым.

## 1. Валидатор: закрыть обход и добавить недостающие проверки

Фундамент. Из 22 проб подсаженных дефектов 11 проходят зелёными — половина

- [ ] 1.2 **Не сломать мета-спеку.** `TEMPLATE_SPEC` (`:84`) — мёртвая константа:

  ровно одно и что оно не используется для обычных спек.
- [ ] 1.3 **Проверять тела разделов.** `find_section(...) is None` (`:218-224,227-234`)

- [ ] 1.4 **Маркер в каждом сценарии**, а не один на тело `## Requirements` (`:312`).

- [ ] 1.8 **Русская форма `#### Сценарий:`** (`runtime/agent-hooks`, `runtime/db-queue-classes`)

- [ ] 1.9 **Несовпавшая строка реестра — ошибка, а не пропуск.** `COMPONENT_ROW_RE`

## 7. Стражи стражам: каждая проверка доказывает свою невакуумность

Требование к валидатору, а не к спекам. Основание: 22 пробы, 11 зелёные на
заведомо плохой спеке; зелёный прогон после правки доказывает только то, что
проверка не выполняется.

- [ ] 7.1 `tests/test_component_spec_validation.py` — **для каждой проверки**
  валидатора тест, который подсаживает дефект и **обязан краснеть**. Тест, который
  не краснеет, — дефект теста, а не проход проверки.
- [ ] 7.2 **Невакуумность самих стражей.** Каждый страж обязан быть проверен на
  подсаженном дефекте: тест, который проходит на пустом множестве, доказывает
  ноль. В проекте это уже стоило работы: правило «словарь синонимов равен таблице»,
  проверенное двумя примерами, краснеет на первом же третьем нарушителе.
- [ ] 7.3 Проверка на **пустом множестве** для каждого правила обхода дерева спек:
  правило, которое находит 0 объектов и проходит, ничего не доказывает.
- [ ] 7.4 Отдельный страж на **ложное срабатывание**: `--strict` на текущем дереве
  даёт 0 ошибок файлов реализации — это должно остаться 0 и после правок реестра
