## Why

Подразделение сводит помощников в одно окно: аудитор спрашивает в чате
Единого рабочего места (кнопка К1-2), вопрос уходит по шине в gateway, и
отвечает тот навык, который выбрал агент. Follow Up — контроль исполнения
поручений и корпус актов проверок ОАРБ — сегодня живёт отдельным
интерфейсом и в это окно не попадает. Нужно, чтобы агент мог его позвать —
и чтобы для этого на машине с агентом ничего не надо было клонировать и
настраивать, как с остальными навыками.

## What Changes

- **Новый навык `workspace/skills/follow_up/`** целиком:
  - `SKILL.md` — инструкция агенту: когда звать Follow Up, когда
    `audit_analyzer`, выводить `answer_md` дословно, как ждать долгую
    сборку карточки; `always: true`;
  - `backend/` — код сервера навыка (MCP-сервер по stdio, семь инструментов,
    поиск по корпусу, карточка исполнения);
  - `tools.json` — описания и схемы инструментов сервера (генерируется из
    его кода);
  - `scripts/follow_up_mcp` (`.cmd` для Windows) — лаунчер сервера:
    стандартная библиотека, любой Python ≥ 3.8;
  - `requirements.txt` — библиотеки навыка сверх закреплённых в корневом
    `requirements.txt` (их навык не переопределяет);
  - `ruff.toml` — `backend/` вне линтера проекта: код сопровождается и
    проверяется в репозитории Follow Up;
  - `.gitignore` — рабочие данные навыка (`data/`, `logs/`, `models/`).
- **Новый модуль `workspace/tools/follow_up.py`** — семь инструментов
  агента `mcp_follow_up_*`. Загрузчик проекта регистрирует их как обычные
  project tools; модуль держит сервер навыка отдельным процессом и
  передаёт ему вызовы по MCP.
- **`project.json`**: `skills.follow_up: {"enabled": true}` — навык в
  единственном реестре; таблиц и индексов в нашем runtime у него нет.
- **Настройки — у агента**: модель — из `config.json` / `.secrets.env`,
  Greenplum и схема — из `channels.postgres` (DSN и `schema`), модели — из
  `workspace/data_store/cache/caches_pipelines/`. В коде нет ни адресов, ни
  имён баз и схем площадки.

## Non-goals

- Изменения в `lib/`, `gateway.py`, `config.py`, `config.json` — их нет.
- Вкладки/формы на стороне Единого рабочего места.
- Гарантия дословного вывода ответа навыка: контракт в `SKILL.md` — тот же,
  что у других навыков, и он остаётся инструкцией модели.

## Impact

`project.json`, новая папка навыка, `workspace/tools/follow_up.py`,
CHANGELOG, README (одна строка), `docs/skill-tool-inventory.md` (одна
строка), тест `tests/test_follow_up_skill.py`. Runtime-код проекта не
меняется, корневой `requirements.txt` — тоже.
