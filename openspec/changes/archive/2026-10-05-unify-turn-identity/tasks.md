# Задачи: личность оборота — один владелец

## 1. Владелец записи

- [x] 1.1 `TurnIdentity`: неизменяемая запись с полями `user_id`,
      `request_id`, `at_seq`, `question_live`
- [x] 1.2 `start_turn` — вход С вопросом: запись заменяется целиком,
      привязка вопроса живая
- [x] 1.3 `note_caller` — вход БЕЗ вопроса: обновляется только снимок,
      чужая привязка вопроса не сбрасывается
- [x] 1.4 `release_question` — снятие привязки; снимок остаётся
- [x] 1.5 `get_request_id` / `question_of` / `identity_of_request` — чтение
      привязки; `current` / `take` — снимок

## 2. Журнал перестаёт быть хранилищем

- [x] 2.1 Снести `_request_index` и `_request_index_lock`
- [x] 2.2 `register_request`: одна запись вместо индекса плюс снимка
- [x] 2.3 `get_request_id` / `clear_request` / `_identity_of_request` —
      делегация владельцу
- [x] 2.4 Чтение привязки в `_enqueue` и антиутечка — чтение записи
- [x] 2.5 Снести фабрику снимка `_turn_identity_snapshot`: форму записи
      строит её владелец

## 3. Одно место чтения

- [x] 3.1 `read_turn_context()` — личность оборота из `RequestContext`
- [x] 3.2 `IDENTITY_KEYS` рядом со сборкой `call_identity()`
- [x] 3.3 `request_id_from()` — единственное место, где спрашивают `request_id`
- [x] 3.4 Хук, клиент платформы, подписчик событий — расчёт у владельца
- [x] 3.5 Три оставшихся чтения `sender_id` — тоже к владельцу
- [x] 3.6 Поля читаются независимо: отсутствие помощника сессии MUST NOT
      обнулять уже прочитанного отправителя

## 4. Стражи

- [x] 4.1 У журнала нет второго носителя (`_request_index`,
      `_turn_identity_snapshot` в исходнике)
- [x] 4.2 Запись личности неизменяема
- [x] 4.3 Атомарность пары: одно чтение записи вместо чтения индекса под
      замком службы
- [x] 4.4 Каждый страж проверен ломанием и восстановлением
