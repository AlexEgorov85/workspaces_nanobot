# CacheProvider

## Назначение

Определяет контракт подсистемы кэширования: источник истины, жизненный цикл snapshot'ов, публикация, атомарность и контракт потребителя. Кэш — локальный DuckDB-слой для быстрого доступа к read-mostly данным, синхронизированным из PostgreSQL.

## Источник истины

- Нормативные инварианты: `docs/TARGET_ARCHITECTURE.md` (раздел Cache).
- Реализация: `docs/ARCHITECTURE.md` и `lib/services/cache_provider*.py` (описательный).

## Ответственность

Компонент отвечает за:
- предоставление кэш-слоя для read-mostly данных;
- синхронизацию данных из PostgreSQL в DuckDB;
- предоставление единого интерфейса доступа к кэшу;
- управление snapshot'ами кэша.

## Граница

Владеет:
- DuckDB файлом кэша на локальном ext4 storage.
- Snapshot'ами таблиц из PostgreSQL.

Может зависеть от:
- PostgreSQL как источника истины.
- Конфигурации `gateway.cache.local_path`.

Не должен зависеть от:
- NFS storage.
- Прямого доступа Skills к DuckDB файлу.

## Публичный контракт

- `CacheProvider.query_sql()` — выполнение SQL запросов к кэшу.
- `CacheProvider.get_schema()` — получение схемы кэша.
- `CacheProvider.explain()` — объяснение плана выполнения.
- `CacheProvider.search_vector()` — векторный поиск.

## Входы

- SQL запросы от потребителей.
- Конфигурация пути к локальному хранилищу.
- Данные для синхронизации из PostgreSQL.

## Выходы

- Результаты SQL запросов.
- Схема кэша.
- Результаты векторного поиска.

## Состояние

Хранит:
- DuckDB файл кэша по пути `gateway.cache.local_path`.
- Snapshot'ы таблиц PostgreSQL.

## Зависимости

- PostgreSQL — источник истины.
- DuckDB — движок кэша.
- Конфигурация проекта.

## Конфигурация

- `gateway.cache.local_path` — путь к локальному DuckDB файлу (ext4, НЕ NFS).

## Жизненный цикл

1. Инициализация: проверка пути к хранилищу (не NFS).
2. Синхронизация: обновление snapshot'ов из PostgreSQL.
3. Обслуживание: обработка запросов потребителей.
4. Публикация: атомарное обновление snapshot'ов.

## Владение данными

Владеет DuckDB файлом кэша. PostgreSQL остаётся источником истины.

## Поведение при ошибке

- Ошибка хранения на NFS: fail fast при старте с явной ошибкой.
- Ошибка синхронизации: логирование, кэш остаётся со stale данными до следующей успешной синхронизации.
- Ошибка запроса: возврат ошибки потребителю, молчаливый fallback на PostgreSQL запрещён.

## Инварианты

- PostgreSQL — источник истины для кэшируемых таблиц.
- Кэш хранится только на локальном ext4 storage.
- Единый интерфейс доступа через `CacheProvider`.

## Запрещённое поведение

Система НЕ ДОЛЖНА:
- записывать DuckDB файл кэша напрямую на NFS mount (эмпирически fails with `PID 0` locking errors).
- вводить второе хранилище кэша помимо `cache_provider.py`.
- молча fallback на PostgreSQL при невалидном кэше; потребители ДОЛЖНЫ быть уведомлены.
- обходить CacheProvider из кода Skills.
- дублировать состояние кэша вне единственного пути к файлу кэша.
