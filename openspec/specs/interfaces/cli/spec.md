# CLI Interface

## Назначение

CLI Interface обеспечивает взаимодействие с системой через командную строку, предоставляя интерфейс для администрирования, отладки и выполнения операций без графического интерфейса.

## Ответственность

- Парсинг командной строки и аргументов
- Выполнение команд управления системой
- Отображение результатов в терминале
- Поддержка интерактивного режима (REPL)
- Логирование сессий CLI
- Интеграция с основными сервисами системы

## Граница

### Владеет
- Парсером командной строки
- Реестром доступных команд
- Форматированием вывода для терминала
- Контекстом CLI-сессии

### Не владеет
- Бизнес-логикой выполняемых операций
- Графическим интерфейсом (это ответственность Streamlit)
- HTTP API (это ответственность Gateway)
- Персистентным хранением состояния CLI

## Контракт

### Публичный интерфейс

```python
class CLIInterface:
    def run(self, args: Optional[List[str]] = None) -> int
    def register_command(
        self,
        name: str,
        handler: Callable[[CommandLine], int],
        description: str,
        aliases: List[str] = None
    ) -> None
    
    def execute_command(
        self,
        command_name: str,
        arguments: Dict[str, Any]
    ) -> int
    
    def start_repl(self) -> None
    def get_available_commands(self) -> List[CommandInfo]
```

### Требования

#### Требование: Выполнение команды

**Сценарий: Запуск команды из командной строки**
- **КОГДА** пользователь запускает CLI с аргументами
- **ТОГДА** парсятся аргументы и определяется команда
- **И** вызывается handler команды с аргументами
- **И** результат выводится в stdout/stderr
- **И** возвращается exit code (0 = успех)

#### Требование: Регистрация команд

**Сценарий: Добавление новой команды**
- **КОГДА** компонент хочет предоставить CLI-команду
- **ТОГДА** вызывается `register_command()` с handler
- **И** команда становится доступной через CLI
- **И** поддерживаются алиасы для удобства

#### Требование: Интерактивный режим

**Сценарий: REPL-сессия для отладки**
- **КОГДА** запущен интерактивный режим
- **ТОГДА** CLI ожидает команды от пользователя
- **И** выполняет команды по одной
- **И** поддерживает историю команд
- **И** завершается по команде `exit` или Ctrl+C

#### Требование: Форматирование вывода

**Сценарий: Читаемый вывод результатов**
- **КОГДА** команда завершает выполнение
- **ТОГДА** результат форматируется для терминала
- **И** поддерживаются различные форматы (text, JSON, table)
- **И** учитывается ширина терминала
- **И** применяется цветовое выделение (опционально)

### Запрещённое поведение

CLI Interface НЕ ДОЛЖЕН:
- Выполнять команды без авторизации (если требуется)
- Раскрывать чувствительные данные в логах
- Блокироваться на неопределённое время
- Игнорировать сигналы прерывания (Ctrl+C)
- Модифицировать состояние системы без подтверждения (для опасных операций)

## Зависимости

### Может зависеть от
- ApplicationContext для доступа к сервисам
- ConfigService для конфигурации CLI
- Logger для логирования сессий
- SessionManager для управления сессиями

### Не должен зависеть от
- Графических библиотек (терминальный интерфейс)
- HTTP-серверов (это ответственность Gateway)
- Конкретных бизнес-компонентов (работает через public API)

## Конфигурация

```yaml
cli:
  enabled: true
  interactive_mode: false
  history_file: "~/.nanobot/cli_history"
  max_history_size: 1000
  output_format: "text"  # text, json, table
  color_output: true
  confirm_dangerous: true
  log_sessions: true
  session_log_dir: "/var/log/nanobot/cli"
  default_timeout_sec: 60.0
  commands:
    enabled:
      - status
      - session
      - config
      - skills
      - cache
      - logs
```

## Жизненный цикл

1. **Инициализация**: Загрузка конфигурации, регистрация команд
2. **Парсинг аргументов**: Обработка командной строки
3. **Выполнение**: Запуск запрошенной команды
4. **Вывод результата**: Форматирование и отображение
5. **Завершение**: Логирование сессии, очистка ресурсов

## Инварианты

- Каждая команда имеет уникальный имя
- Exit code 0 означает успех, non-zero — ошибку
- История команд сохраняется между сессиями (если включено)
- Опасные команды требуют подтверждения
- Таймаут применяется ко всем командам

## Поведение при ошибке

- Неизвестная команда → сообщение об ошибке, список доступных команд
- Ошибка выполнения → вывод ошибки, exit code != 0
- Таймаут команды → прерывание, сообщение о таймауте
- Ctrl+C → graceful прерывание текущей команды
