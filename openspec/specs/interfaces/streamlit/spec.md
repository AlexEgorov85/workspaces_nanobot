# Streamlit Interface

## Назначение

Streamlit Interface обеспечивает интерактивный веб-интерфейс для работы с системой через фреймворк Streamlit, предоставляя удобный UI для пользователей без необходимости разработки frontend отдельно.

## Ответственность

- Отображение интерфейса приложения в браузере
- Обработка пользовательского ввода через виджеты Streamlit
- Визуализация результатов работы Skills
- Управление сессиями пользователей
- Интеграция с backend через Gateway или напрямую
- Отображение логов и статуса системы

## Граница

### Владеет
- UI-компонентами Streamlit
- Состоянием UI (session_state)
- Форматированием отображаемых данных
- Навигацией между страницами приложения

### Не владеет
- Бизнес-логикой обработки запросов
- Хранением данных (делегирует backend)
- Аутентификацией (может использовать внешнюю)
- Генерацией HTML/CSS/JS (делегает Streamlit)

## Контракт

### Публичный интерфейс

```python
class StreamlitInterface:
    def run(self, config: StreamlitConfig) -> None
    def register_page(
        self,
        name: str,
        icon: str,
        render_func: Callable[[], None]
    ) -> None
    
    def get_session_state(self) -> SessionState
    def display_message(
        self,
        role: str,
        content: str,
        metadata: Optional[Dict] = None
    ) -> None
    
    def display_error(self, error: Exception) -> None
    def refresh_display(self) -> None
```

### Требования

#### Требование: Отображение интерфейса

**Сценарий: Запуск Streamlit приложения**
- **КОГДА** запускается Streamlit интерфейс
- **ТОГДА** инициализируется приложение с конфигурацией
- **И** регистрируются доступные страницы
- **И** открывается браузер на порту Streamlit
- **И** приложение готово к приёму пользователей

#### Требование: Навигация по страницам

**Сценарий: Переключение между разделами**
- **КОГДА** пользователь выбирает страницу в sidebar
- **ТОГДА** отображается соответствующая страница
- **И** сохраняется контекст предыдущей страницы
- **И** загружается состояние новой страницы

#### Требование: Отображение сообщений

**Сценарий: Показ диалога с ботом**
- **КОГДА** Skill возвращает результат
- **ТОГДА** сообщение форматируется и отображается
- **И** поддерживаются различные типы контента (текст, код, таблицы)
- **И** сообщения сохраняются в истории сессии

#### Требование: Обработка ввода пользователя

**Сценарий: Приём пользовательского запроса**
- **КОГДА** пользователь вводит текст в chat_input
- **ТОГДА** ввод передаётся в систему обработки
- **И** отображается индикатор выполнения
- **И** результат отображается после обработки

### Запрещённое поведение

Streamlit Interface НЕ ДОЛЖЕН:
- Выполнять бизнес-логику напрямую (только через API)
- Хранить чувствительные данные в session_state
- Блокировать UI надолго без индикатора прогресса
- Раскрывать внутренние ошибки пользователю
- Игнорировать ограничения размера загружаемых файлов

## Зависимости

### Может зависеть от
- Gateway Interface для API вызовов
- ApplicationContext для прямого доступа к сервисам
- ConfigService для конфигурации UI
- Logger для логирования действий пользователя

### Не должен зависеть от
- Конкретных бизнес-компонентов
- Других frontend-фреймворков
- Прямых соединений с БД

## Конфигурация

```yaml
streamlit:
  enabled: true
  host: "0.0.0.0"
  port: 8501
  theme:
    primaryColor: "#FF6B6B"
    backgroundColor: "#FFFFFF"
    secondaryBackgroundColor: "#F0F2F6"
    font: "sans serif"
  layout: "centered"  # centered, wide
  show_sidebar: true
  pages:
    - name: "Chat"
      icon: "💬"
      default: true
    - name: "Skills"
      icon: "🛠️"
    - name: "Settings"
      icon: "⚙️"
    - name: "Logs"
      icon: "📋"
  upload:
    max_size_mb: 10
    allowed_extensions:
      - ".pdf"
      - ".docx"
      - ".xlsx"
      - ".txt"
      - ".jpg"
      - ".png"
  chat:
    max_history_messages: 50
    show_timestamps: true
    enable_markdown: true
```

## Жизненный цикл

1. **Инициализация**: Загрузка конфигурации, регистрация страниц
2. **Запуск сервера**: Старт Streamlit server
3. **Обработка запросов**: Рендеринг UI, обработка ввода
4. **Управление сессией**: Сохранение состояния между rerun
5. **Завершение**: Остановка сервера при shutdown

## Состояние

```python
{
    "current_page": str,
    "chat_history": List[Message],
    "user_preferences": Dict[str, Any],
    "active_skills": List[str],
    "last_updated": datetime
}
```

## Инварианты

- Каждая страница имеет уникальное имя
- Session_state сохраняется между rerun одной сессии
- Максимальная история сообщений не превышается
- Загруженные файлы проверяются на безопасность

## Поведение при ошибке

- Ошибка рендеринга → отображение error box с безопасным сообщением
- Ошибка загрузки файла → сообщение о проблеме с файлом
- Потеря соединения → индикация offline режима
- Timeout запроса → сообщение о таймауте, предложение повторить

## Потребители

- End Users — основной интерфейс для работы с системой
- Business Users — работа с Skills без программирования
- Analysts — просмотр логов и результатов
- Administrators — базовое управление через UI
