# ConfigService

## Назначение

Предоставляет централизованный сервис для чтения и разрешения конфигурации проекта. ConfigService обеспечивает единый источник конфигурационных данных для всех компонентов системы.

## Источник истины

- Нормативные инварианты: `docs/TARGET_ARCHITECTURE.md` (раздел Configuration).
- Реализация: `docs/ARCHITECTURE.md` и `lib/services/config_service.py` (описательный).

## Ответственность

Компонент отвечает за:
- чтение конфигурации из `project.json`, `config.json`, `.secrets.env`;
- разрешение профиля (prod/test);
- применение profile-specific overlays;
- предоставление конфигурации другим компонентам.

## Граница

Владеет:
- процессом загрузки конфигурации.
- разрешением профиля.
- кэшем конфигурации.

Может зависеть от:
- файловой системы для чтения конфигов.
- переменных окружения.

Не должен зависеть от:
- бизнес-логики Skills.
- runtime-компонентов после инициализации.

## Публичный контракт

- `ConfigService.get(key, default=None)` — получение значения по ключу.
- `ConfigService.get_section(section)` — получение раздела конфигурации.
- `ConfigService.profile` — активный профиль.
- `ConfigService.reload()` — перезагрузка конфигурации (если поддерживается).

## Входы

- Файлы конфигурации (`project.json`, `config.json`).
- Переменные окружения (`.secrets.env`).
- CLI аргументы (например, `--profile`).

## Выходы

- Разрешённая конфигурация.
- Активный профиль.

## Состояние

Хранит:
- Кэш загруженной конфигурации.
- Разрешённый профиль.

## Зависимости

- Файловая система.
- Переменные окружения.
- Механизм слияния JSON.

## Конфигурация

- `project.json` — основная конфигурация.
- `config.json` — дополнительная конфигурация.
- `.secrets.env` — секреты.

## Жизненный цикл

1. Загрузка файлов конфигурации при старте.
2. Применение CLI флагов (если указаны).
3. Разрешение профиля.
4. Применение profile-specific overlays.
5. Предоставление доступа через getter'ы.
6. Опциональная перезагрузка (если поддерживается).

## Владение данными

Владеет кэшем конфигурации и профилем.

## Поведение при ошибке

- Ошибка чтения файла: fail fast при старте.
- Ошибка парсинга JSON: явная ошибка с диагностикой.
- Отсутствие ключа: возврат default или None.
- Ошибка разрешения профиля: fail fast (нет профиля по умолчанию).

## Инварианты

- Конфигурация загружается до инициализации runtime.
- Профиль разрешается один раз и не меняется.
- Все компоненты получают конфигурацию из единого источника.

## Запрещённое поведение

Система НЕ ДОЛЖНА:
- читать конфигурацию напрямую из файлов вне ConfigService.
- позволять переключение профиля после инициализации.
- возвращаться к профилю по умолчанию при ошибке разрешения.
- молча игнорировать неизвестные ключи конфигурации.
- вводить третий профиль без явного OpenSpec change.

## Потребители

- `ApplicationContext` — для передачи инфраструктуре.
- `AgentFactory` — для чтения конфигурации Skills.
- Channels — для настройки подключений.
- Services (CacheProvider, VectorIndexService, DbLoggingService).

## Реализация

Основная реализация:
- `lib/services/config_service.py:ConfigService`

Связанные компоненты:
- `lib/core/project_settings.py` — разрешение профиля.
- `lib/core/application_context.py:ApplicationContext`

## Проверка

- Архитектурные тесты: проверка единого источника конфигурации.
- Тесты профиля: проверка fail fast при ошибке разрешения.
- Code review: проверка отсутствия прямых чтений файлов конфигурации.
