# Audit Analyzer Skill

## Назначение

Audit Analyzer Skill обеспечивает автоматизированный анализ аудиторских данных, выявление аномалий, генерацию выводов и рекомендаций на основе предметной логики аудита.

## Ответственность

- Анализ структурированных аудиторских данных
- Выявление паттернов и аномалий в данных
- Генерация сводных отчётов по результатам аудита
- Поддержка различных режимов анализа (predefined, vector, generated_sql)
- Интеграция с источниками данных через стандартные интерфейсы
- Формирование рекомендаций на основе выявленных проблем

## Граница

### Владеет
- Предметной логикой аудиторского анализа
- Правилами выявления аномалий
- Шаблонами отчётов по аудиту
- Конфигурацией параметров анализа

### Не владеет
- Исходными данными аудита (получает извне)
- Хранением исторических данных аудита
- Интерфейсом отображения результатов (делегирует UI)
- Принятием решений по результатам аудита

### Требования

#### Требование: Анализ по predefined сценарию

**Сценарий: Выполнение заранее определённого анализа**
- **КОГДА** выбран режим `predefined`
- **ТОГДА** применяются фиксированные правила анализа
- **И** используются hardcoded шаблоны проверки
- **И** результат следует стандартному формату отчёта

#### Требование: Анализ через векторный поиск

**Сценарий: Поиск похожих случаев аудита**
- **КОГДА** выбран режим `vector`
- **ТОГДА** выполняется поиск по векторному индексу исторических аудитов
- **И** находятся похожие кейсы по семантической близости
- **И** рекомендации формируются на основе успешных прошлых аудитов

#### Требование: Анализ через генерацию SQL

**Сценарий: Динамический запрос к данным**
- **КОГДА** выбран режим `generated_sql`
- **ТОГДА** генерируется SQL-запрос на основе параметров анализа
- **И** запрос проходит валидацию через SqlSafety
- **И** выполняется к данным аудита
- **И** результаты анализируются правилами аудита

#### Требование: Выявление аномалий

**Сценарий: Обнаружение отклонений в данных**
- **КОГДА** данные переданы на анализ
- **ТОГДА** применяются статистические методы обнаружения аномалий
- **И** записи с отклонением > threshold помечаются как аномалии
- **И** каждая аномалия включает объяснение причины

#### Требование: Генерация отчёта

**Сценарий: Формирование итогового документа**
- **КОГДА** анализ завершён
- **ТОГДА** генерируется отчёт по шаблону
- **И** включаются все выявленные проблемы
- **И** добавляются рекомендации по устранению
- **И** отчёт структурирован для удобного чтения

### Запрещённое поведение

Audit Analyzer Skill НЕ ДОЛЖЕН:
- Молчаливо переключаться между режимами анализа
- Возвращать результаты без указания уровня уверенности
- Игнорировать ошибки доступа к данным
- Раскрывать чувствительные данные в логах
- Создавать собственные кэши (использовать CacheProvider)
- Выполнять запросы без ограничения количества записей

## Зависимости

### Может зависеть от
- VectorIndexService для vector mode
- SqlSafety для generated_sql mode
- CacheProvider для кэширования результатов
- DbLoggingService для логирования выполнения
- DuckDBSync для аналитики больших объёмов

### Не должен зависеть от
- Прямых соединений с БД
- Других Skills
- Внешних систем аудита

## Жизненный цикл

1. **Инициализация**: Загрузка конфигурации, правил аудита
2. **Приём данных**: Получение данных для анализа
3. **Выбор режима**: Определение режима выполнения
4. **Анализ**: Применение правил, выявление аномалий
5. **Генерация отчёта**: Формирование структурированного результата
6. **Кэширование**: Сохранение результатов (опционально)

## Инварианты

- Режим анализа явно указан перед выполнением
- Все аномалии включают уровень уверенности (confidence)
- Отчёт всегда содержит резюме (executive summary)
- Максимальное количество записей не превышается
- Чувствительные данные маскируются в логах

## Поведение при ошибке

- Ошибка доступа к данным → AuditDataError с контекстом
- Ошибка генерации SQL → GenerationError, fallback на predefined
- Превышение лимита записей → LimitExceededError с предложением фильтрации
- Ошибка шаблона отчёта → ReportGenerationError

## Потребители

- Users — запрос аудиторского анализа через UI
- Analysts — автоматизация рутинных проверок
- Compliance Officers — проверка соответствия требованиям
- Management — сводные отчёты по аудиту

- Тесты на каждый режим выполнения
- Тесты на точность выявления аномалий
- Тесты на генерацию отчётов
- Тесты на обработку ошибок

- Валидация качества рекомендаций
- Проверка читаемости отчётов
- Анализ производительности на больших данных
