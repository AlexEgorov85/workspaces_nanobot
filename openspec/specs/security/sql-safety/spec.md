# SQL Safety

## Назначение

SQL Safety обеспечивает защиту от SQL-инъекций и других уязвимостей, связанных с выполнением SQL-запросов, предоставляя безопасные механизмы построения и выполнения запросов к базе данных.

## Ответственность

- Валидация SQL-запросов перед выполнением
- Параметризация запросов для предотвращения инъекций
- Контроль разрешённых операций (SELECT, INSERT, UPDATE, DELETE)
- Блокировка опасных конструкций (DROP, TRUNCATE, EXEC и др.)
- Аудит выполняемых запросов
- Ограничение сложности запросов (время выполнения, количество строк)

## Граница

### Владеет
- Whitelist разрешённых SQL-операций
- Механизмом параметризации запросов
- Политикой безопасности SQL
- Журналом аудита запросов

### Не владеет
- Бизнес-логикой формирования запросов
- Схемой базы данных
- Механизмом выполнения запросов (делегирует DB driver)
- Управлением соединениями (делегирует connection pool)

## Контракт

### Публичный интерфейс

```python
class SqlSafety:
    def validate_query(
        self,
        query: str,
        allowed_operations: Optional[List[str]] = None
    ) -> ValidationResult
    
    def parameterize_query(
        self,
        query_template: str,
        parameters: Dict[str, Any]
    ) -> Tuple[str, List[Any]]
    
    def is_safe_operation(self, operation: str) -> bool
    def sanitize_identifier(self, identifier: str) -> str
    def escape_string(self, value: str) -> str
    def audit_query(
        self,
        query: str,
        context: QueryContext
    ) -> None
    
    def get_blocked_patterns(self) -> List[str]
```

### Требования

#### Требование: Валидация запроса

**Сценарий: Проверка безопасности запроса**
- **КОГДА** формируется SQL-запрос к выполнению
- **ТОГДА** вызывается `validate_query()` с текстом запроса
- **И** проверяется наличие запрещённых операций
- **И** проверяется наличие запрещённых паттернов
- **И** при нарушении выбрасывается исключение SecurityError

#### Требование: Параметризация запроса

**Сценарий: Безопасная подстановка параметров**
- **КОГДА** требуется выполнить запрос с параметрами
- **ТОГДА** вызывается `parameterize_query()` с шаблоном и параметрами
- **И** параметры заменяются на плейсхолдеры ($1, $2, ...)
- **И** значения передаются отдельно от запроса
- **И** исключается возможность SQL-инъекции

#### Требование: Whitelist операций

**Сценарий: Разрешение только безопасных операций**
- **КОГДА** проверяется допустимость операции
- **ТОГДА** операция сверяется с whitelist (SELECT, INSERT, UPDATE, DELETE)
- **И** опасные операции (DROP, TRUNCATE, ALTER, EXEC) блокируются
- **И** whitelist может быть настроен через конфигурацию

#### Требование: Санитизация идентификаторов

**Сценарий: Безопасное использование имён таблиц/колонок**
- **КОГДА** требуется использовать динамический идентификатор
- **ТОГДА** вызывается `sanitize_identifier()`
- **И** проверяется соответствие шаблону [a-zA-Z_][a-zA-Z0-9_]*
- **И** идентификатор заключается в двойные кавычки
- **И** недопустимые идентификаторы отклоняются

### Запрещённое поведение

SQL Safety НЕ ДОЛЖЕН:
- Позволять выполнение запросов без валидации
- Пропускать запросы с запрещёнными операциями
- Позволять конкатенацию пользовательских данных в запрос
- Игнорировать попытки обхода через кодировку/комментарии
- Логировать полные запросы с чувствительными данными
- Блокировать легитимные сложные запросы (JOIN, подзапросы)

## Зависимости

### Может зависеть от
- ConfigService для настройки политик безопасности
- Logger для аудита подозрительных запросов
- DbLoggingService для журнала запросов

### Не должен зависеть от
- Конкретных бизнес-запросов
- ORM или query builders (работает на уровне SQL)
- Внешних систем безопасности

## Конфигурация

```yaml
sql_safety:
  enabled: true
  allowed_operations:
    - SELECT
    - INSERT
    - UPDATE
    - DELETE
  blocked_patterns:
    - "DROP\\s+TABLE"
    - "TRUNCATE\\s+"
    - "ALTER\\s+"
    - "CREATE\\s+(USER|ROLE)"
    - "EXEC(UTE)?\\s*\\("
    - "--"  # комментарии
    - "/\\*"  # блочные комментарии
  max_query_length: 10000
  max_parameters: 100
  max_join_tables: 10
  max_subquery_depth: 3
  audit_all_queries: false
  audit_blocked_only: true
  log_parameter_values: false  # не логировать значения параметров
```

## Жизненный цикл

1. **Инициализация**: Загрузка политик безопасности, паттернов
2. **Валидация**: Проверка каждого запроса перед выполнением
3. **Параметризация**: Преобразование запросов с параметрами
4. **Аудит**: Логирование подозрительных попыток
5. **Завершение**: Сброс статистики, закрытие логов

## Инварианты

- Все запросы проходят валидацию перед выполнением
- Параметры всегда параметризуются, никогда не конкатенируются
- Заблокированные запросы логируются независимо от настроек аудита
- Whitelist операций применяется ко всем запросам без исключений

## Поведение при ошибке

- Нарушение политики → исключение SecurityError, аудит
- Недопустимый идентификатор → исключение ValueError
- Превышение лимитов → исключение QueryTooComplexError
- Ошибка валидации → блокировка запроса по умолчанию (fail-safe)

## Проверка

### Автоматическая проверка
- Тесты на обнаружение SQL-инъекций
- Тесты на блокировку опасных операций
- Тесты на корректную параметризацию
- Тесты на санитизацию идентификаторов
- Тесты на обход через различные техники

### Ручная проверка
- Аудит заблокированных запросов
- Анализ ложных срабатываний
- Проверка производительности на сложных запросах
