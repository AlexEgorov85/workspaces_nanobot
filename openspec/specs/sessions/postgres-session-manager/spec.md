# PGSessionManager

## Назначение

Управляет сессиями пользователей в PostgreSQL. PGSessionManager обеспечивает сохранение и извлечение состояния сессии, включая сообщения, метаданные и историю взаимодействий.

## Источник истины

- Нормативные инварианты: `docs/TARGET_ARCHITECTURE.md` (раздел Session Management).
- Реализация: `docs/ARCHITECTURE.md` и `lib/session/pg_session_manager.py` (описательный).

## Ответственность

Компонент отвечает за:
- создание новых сессий;
- сохранение сообщений сессии в PostgreSQL;
- извлечение истории сессии;
- управление метаданными сессии.

## Граница

Владеет:
- таблицами сессий в PostgreSQL.
- историей сообщений сессии.
- метаданными сессии.

Может зависеть от:
- PostgreSQL подключения.
- Конфигурации таблиц сессий.

Не должен зависеть от:
- бизнес-логики Skills.
- ApplicationContext (сессии хранятся вне его).

## Публичный контракт

- `PGSessionManager.create_session(user_id, metadata)` — создание сессии.
- `PGSessionManager.get_session(session_id)` — получение сессии.
- `PGSessionManager.save_message(session_id, message)` — сохранение сообщения.
- `PGSessionManager.get_history(session_id, limit)` — получение истории.
- `PGSessionManager.close_session(session_id)` — закрытие сессии.

## Входы

- Запросы на создание/чтение/запись сессий.
- Сообщения для сохранения.
- Метаданные сессии.

## Выходы

- ID созданной сессии.
- Данные сессии и история сообщений.
- Подтверждения сохранения.

## Состояние

Хранит:
- Кэш активных сессий (если применимо).
- Подключения к PostgreSQL.

## Зависимости

- PostgreSQL база данных.
- Конфигурация таблиц сессий.
- TableRegistry для регистрации таблиц.

## Конфигурация

- Имена таблиц сессий (profile-specific для test).
- Настройки подключения к PostgreSQL.

## Жизненный цикл

1. Инициализация при старте runtime.
2. Создание сессий по запросу.
3. Сохранение сообщений в реальном времени.
4. Извлечение истории по запросу.
5. Остановка подключений при shutdown.

## Владение данными

Владеет таблицами сессий в PostgreSQL и историей сообщений.

## Поведение при ошибке

- Ошибка создания сессии: возврат явной ошибки.
- Ошибка сохранения сообщения: логирование и возврат ошибки.
- Ошибка чтения истории: возврат пустого результата или ошибки.
- Ошибка подключения к PostgreSQL: fail fast.

## Инварианты

- Сессионное состояние хранится в PostgreSQL, не в ApplicationContext.
- Каждая сессия имеет уникальный ID.
- Сообщения сохраняются в порядке получения.

## Запрещённое поведение

Система НЕ ДОЛЖНА:
- хранить сессионные данные в ApplicationContext.
- терять сообщения без явного логирования ошибки.
- позволять доступ к чужим сессиям без авторизации.
- дублировать хранение сессий вне PostgreSQL.

## Потребители

- AgentLoop — для сохранения истории диалога.
- Skills — для доступа к контексту сессии.
- Gateway — для управления сессиями пользователей.
