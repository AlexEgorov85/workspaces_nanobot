# Система хуков

## Назначение

Система хуков обеспечивает механизм расширения функциональности системы через точки расширения (hooks), позволяя подключать кастомную логику в определённые моменты жизненного цикла без модификации основного кода.

## Ответственность

- Регистрация хуков для различных событий системы
- Вызов хуков в точках расширения
- Управление приоритетами выполнения хуков
- Обработка ошибок в хуках без прерывания основного потока
- Поддержка синхронных и асинхронных хуков

## Граница

### Владеет
- Реестром зарегистрированных хуков
- Механизмом вызова хуков
- Приоритетами выполнения
- Контекстом, передаваемым хукам

### Не владеет
- Бизнес-логикой хуков (предоставляется внешними модулями)
- Точками расширения в коде (определяются разработчиками компонентов)
- Результатами выполнения хуков (если не указано явно)

## Контракт

### Публичный интерфейс

```python
class HookSystem:
    def register_hook(
        self,
        hook_name: str,
        handler: Callable,
        priority: int = 0,
        hook_id: Optional[str] = None
    ) -> str
    
    def unregister_hook(self, hook_id: str) -> bool
    def trigger_hook(
        self,
        hook_name: str,
        *args,
        **kwargs
    ) -> List[Any]
    
    async def trigger_hook_async(
        self,
        hook_name: str,
        *args,
        **kwargs
    ) -> List[Any]
    
    def get_hooks(self, hook_name: str) -> List[HookInfo]
    def clear_hooks(self, hook_name: Optional[str] = None) -> None
```

### Требования

#### Требование: Регистрация хука

**Сценарий: Добавление обработчика события**
- **КОГДА** компонент хочет реагировать на событие системы
- **ТОГДА** вызывается `register_hook()` с именем хука и handler
- **И** хук регистрируется с указанием приоритета
- **И** возвращается уникальный ID хука для последующей отмены

#### Требование: Вызов хуков

**Сценарий: Уведомление подписчиков о событии**
- **КОГДА** происходит событие системы
- **ТОГДА** вызывается `trigger_hook()` с именем события
- **И** все зарегистрированные хуки вызываются по приоритету
- **И** результаты собираются в список и возвращаются

#### Требование: Приоритеты выполнения

**Сценарий: Контроль порядка выполнения хуков**
- **КОГДА** зарегистрировано несколько хуков на одно событие
- **ТОГДА** хуки выполняются в порядке убывания приоритета
- **И** хуки с одинаковым приоритетом выполняются в порядке регистрации

#### Требование: Обработка ошибок

**Сценарий: Изоляция сбоев в хуках**
- **КОГДА** хук выбрасывает исключение
- **ТОГДА** исключение логируется
- **И** выполнение продолжается со следующим хуком
- **И** основное приложение не прерывается

### Запрещённое поведение

Система хуков НЕ ДОЛЖНА:
- Прерывать основной поток при ошибке в хуке
- Позволять хукам модифицировать реестр хуков во время выполнения
- Гарантировать порядок хуков с одинаковым приоритетом между запусками
- Блокировать основное приложение надолго (таймаут на хуки)
- Передавать чувствительные данные в хуки без явного согласия

## Зависимости

### Может зависеть от
- Logger для записи ошибок хуков
- ConfigService для конфигурации таймаутов
- ApplicationContext для интеграции

### Не должен зависеть от
- Конкретных реализаций хуков
- Бизнес-компонентов (хуки подключаются извне)

## Конфигурация

```yaml
hooks:
  enabled: true
  default_priority: 0
  timeout_per_hook_sec: 5.0
  max_hooks_per_event: 50
  log_all_executions: false
  log_errors: true
  async_support: true
```

## Жизненный цикл

1. **Инициализация**: Создание реестра хуков, загрузка конфигурации
2. **Регистрация**: Компоненты регистрируют хуки через API
3. **Выполнение**: Хуки вызываются в точках расширения
4. **Завершение**: Очистка реестра при shutdown

## Состояние

```python
{
    "hooks": Dict[str, List[HookRegistration]],
    "hook_counter": int,
    "execution_log": List[HookExecutionRecord],
    "is_shutting_down": bool
}
```

## Инварианты

- Каждый хук имеет уникальный ID
- Хуки выполняются строго по приоритету (descending)
- Ошибка в одном хуке не влияет на выполнение других
- Таймаут применяется к каждому хуку индивидуально
- При shutdown хуки не вызываются

## Поведение при ошибке

- Ошибка в хуке → логирование, продолжение со следующим хуком
- Таймаут хука → прерывание этого хука, продолжение со следующим
- Ошибка регистрации → исключение, реестр не меняется
- Некорректный hook_name → исключение ValueError

## Потребители

- Skills — расширение логики обработки запросов
- Session Manager — хуки жизненного цикла сессий
- AgentLoop — хуки перед/после выполнения агента
- Logging — аудиторские хуки
- External Integrations — подключение внешних систем

## Проверка

### Автоматическая проверка
- Тесты на регистрацию/отмену хуков
- Тесты на приоритеты выполнения
- Тесты на обработку ошибок
- Тесты на асинхронные хуки
- Тесты на таймауты

### Ручная проверка
- Анализ производительности при множестве хуков
- Проверка изоляции ошибок
- Аудит зарегистрированных хуков
