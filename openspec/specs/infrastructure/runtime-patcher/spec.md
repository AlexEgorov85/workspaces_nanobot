# Runtime Patcher

## Назначение

Runtime Patcher обеспечивает динамическую модификацию поведения системы во время выполнения без перезапуска процесса, позволяя применять хотфиксы, обновлять конфигурацию и изменять логику компонентов.

## Ответственность

- Динамическая замена методов и функций в работающих объектах
- Применение патчей к экземплярам классов
- Откат применённых патчей
- Ведение журнала применённых изменений
- Валидация безопасности патчей перед применением

## Граница

### Владеет
- Реестром активных патчей
- Механизмом замены атрибутов объектов
- Журналом изменений (патч-лог)
- Правилами безопасности для патчей

### Не владеет
- Исходным кодом компонентов (патчи применяются в памяти)
- Персистентным хранением патчей
- Бизнес-логикой, которую изменяют патчи
- Управлением версиями кода

## Контракт

### Публичный интерфейс

```python
class RuntimePatcher:
    def apply_patch(
        self,
        target_object: object,
        attribute_name: str,
        new_implementation: Callable,
        patch_id: str,
        description: str = ""
    ) -> PatchHandle
    
    def revert_patch(self, handle: PatchHandle) -> bool
    def revert_all_patches(self) -> None
    def get_active_patches(self) -> List[PatchInfo]
    def is_patched(self, target_object: object, attribute_name: str) -> bool
    def get_original(
        self,
        target_object: object,
        attribute_name: str
    ) -> Optional[Callable]
```

### Требования

#### Требование: Применение патча

**Сценарий: Замена метода во время выполнения**
- **КОГДА** требуется изменить поведение компонента без перезапуска
- **ТОГДА** вызывается `apply_patch()` с новым implementation
- **И** оригинальный метод сохраняется
- **И** новый метод заменяет оригинал в объекте
- **И** патч регистрируется в реестре с уникальным ID

#### Требование: Откат патча

**Сценарий: Восстановление оригинального поведения**
- **КОГДА** требуется отменить применённый патч
- **ТОГДА** вызывается `revert_patch()` с handle патча
- **И** оригинальный метод восстанавливается
- **И** патч удаляется из реестра активных

#### Требование: Получение оригинала

**Сценарий: Доступ к исходной реализации**
- **КОГДА** требуется вызвать оригинальную логику из патча
- **ТОГДА** вызывается `get_original()` для получения оригинала
- **И** возвращается сохранённая оригинальная функция
- **И** патч может обернуть оригинал (decorator pattern)

#### Требование: Безопасность патчей

**Сценарий: Предотвращение опасных изменений**
- **КОГДА** применяется патч
- **ТОГДА** проверяется валидность целевого объекта
- **И** проверяется наличие атрибута для замены
- **И** запрещается патчинг критических системных компонентов

### Запрещённое поведение

Runtime Patcher НЕ ДОЛЖЕН:
- Позволять патчинг приватных методов с именами `__dunder__`
- Применять патчи к immutable объектам
- Терять оригинальные реализации при ошибке патчинга
- Позволять рекурсивный патчинг одного атрибута
- Модифицировать классы вместо экземпляров (если не указано явно)
- Патчить компоненты вне разрешённого whitelist

## Зависимости

### Может зависеть от
- Logger для записи применённых патчей
- ConfigService для whitelist компонентов
- ApplicationContext для доступа к компонентам

### Не должен зависеть от
- Конкретных бизнес-компонентов
- Внешних источников патчей
- Систем сборки кода

## Конфигурация

```yaml
runtime_patcher:
  enabled: true
  whitelist:
    - "lib.skills.*"
    - "lib.services.*"
  blacklist:
    - "lib.core.application_context.*"
    - "lib.core.channel_manager.*"
  log_all_patches: true
  allow_dunder_methods: false
  max_patches_per_object: 10
```

## Жизненный цикл

1. **Инициализация**: Загрузка whitelist/blacklist
2. **Применение патчей**: Динамическая замена методов по запросу
3. **Мониторинг**: Отслеживание активных патчей
4. **Откат**: Восстановление оригиналов при необходимости
5. **Завершение**: Автоматический откат всех патчей при shutdown (опционально)

## Состояние

```python
{
    "active_patches": Dict[str, PatchInfo],
    "originals_cache": Dict[Tuple[object, str], Callable],
    "patch_counter": int,
    "is_shutting_down": bool
}
```

## Инварианты

- Каждый патч имеет уникальный ID в пределах сессии
- Оригинальная реализация сохраняется до отката патча
- Один атрибут не может быть запатчен дважды без отката
- Whitelist/blacklist применяются ко всем операциям патчинга
- При shutdown патчи могут быть автоматически откатаны

## Поведение при ошибке

- Ошибка применения патча → исключение, состояние не меняется
- Ошибка отката → логирование, попытка восстановления
- Попытка патча запрещённого компонента → исключение SecurityError
- Переполнение лимита патчей → исключение LimitExceeded

## Потребители

- Skills — обновление логики без перезапуска
- Services — применение хотфиксов
- Testing — мокирование компонентов в integration tests
- Debugging — временная инструментация кода

## Проверка

### Автоматическая проверка
- Тесты на применение и откат патчей
- Тесты на получение оригинальной реализации
- Тесты на безопасность (whitelist/blacklist)
- Тесты на множественные патчи одного объекта

### Ручная проверка
- Анализ влияния на производительность
- Проверка отсутствия утечек памяти
- Аудит журнала патчей
