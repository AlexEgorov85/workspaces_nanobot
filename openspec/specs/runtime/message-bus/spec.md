# MessageBus (MessageExchange)

## Назначение

Предоставляет общий движок обмена сообщениями для каналов (`PostgresChannel`, `RedisChannel`). Абстрагирует транспортно-независимую оркестрацию: поллинг входящих сообщений, ограничение параллельности, обработку вложений, фильтрацию служебных сообщений и priority polling для команд управления.

## Ответственность

Компонент отвечает за:
- цикл поллинга входящих сообщений с backoff при ошибках;
- ограничение параллельности через семафор и множество in-flight запросов;
- обработку вложений `media` через единый кодек;
- фильтрацию служебных сообщений (reasoning/progress/turn_end);
- priority polling для команд управления (`/stop`, `/restart`, `/status`);
- управление жизненным циклом polling loop (start/stop).

## Граница

Владеет:
- логикой оркестрации обмена сообщениями;
- управлением слотами параллельности;
- lifecycle polling loop.

Может зависеть от:
- транспорта-канала (`PostgresChannel`, `RedisChannel`);
- модуля `utils.media` для сериализации/десериализации вложений;
- asyncio event loop.

Не должен зависеть от:
- конкретной реализации транспорта (SQL vs Redis);
- бизнес-логики обработки сообщений;
- сессионных данных.

## Публичный контракт

- `MessageExchange(channel, max_concurrent=1, poll_interval=5.0, error_backoff=1.0)` — создание движка для канала.
- `start()` — запуск polling loop.
- `stop()` — остановка polling loop.
- `acquire_slot()` — асинхронное получение слота для обработки сообщения.
- `release_slot(key=None)` — освобождение слота.
- `add_inflight(key)` — добавление ключа в множество in-flight.
- `discard_inflight(key)` — удаление ключа из in-flight.
- `is_slot_free()` — проверка доступности слота.
- `embed(media)` — сериализация вложений для хранения.
- `decode(media, session_key)` — десериализация вложений для runtime.
- `resolve(media)` — распаковка media в пути и подсказки.

## Входы

- `channel` — транспортный канал с методами `poll_inbound()` и опционально `poll_priority_inbound()`;
- конфигурация параллельности (`max_concurrent`);
- интервалы polling и backoff.

## Выходы

- Диспатч входящих сообщений агенту через канал;
- Сериализованные/десериализованные вложения;
- Управление слотами параллельности.

## Состояние

Хранит:
- `_semaphore` — семафор ограничения параллельности;
- `_inflight` — множество ключей активных запросов;
- `_running` — флаг работы polling loop;
- `_poll_task` — задача asyncio polling loop.

## Зависимости

- `utils.media.serialize` — сериализация вложений;
- `utils.media.deserialize` — десериализация вложений;
- `utils.media.resolve_paths_and_hints` — распаковка путей;
- `asyncio.Semaphore` — ограничение параллельности;
- `asyncio.create_task` — создание задач polling.

## Конфигурация

- `max_concurrent` — максимальное число параллельных обработчиков (по умолчанию 1);
- `poll_interval` — интервал опроса канала при отсутствии сообщений (по умолчанию 5.0 сек);
- `error_backoff` — задержка при ошибке polling (по умолчанию 1.0 сек).

## Жизненный цикл

1. `__init__` — инициализация семафора, множеств, флагов.
2. `start()` — запуск бесконечного polling loop в background task.
3. Polling cycle:
   - Проверка priority inbound (если реализовано каналом);
   - Если слот свободен — обычный polling;
   - Иначе — ожидание по `poll_interval`.
4. `stop()` — отмена polling task, очистка ресурсов.

## Владение данными

Владеет:
- множеством `_inflight` ключей активных запросов;
- состоянием семафора параллельности;
- флагом `_running` и ссылкой на polling task.

Не владеет:
- самими сообщениями (передаются каналу);
- сессионными данными.

## Поведение при ошибке

- Ошибка polling логируется, применяется `error_backoff`;
- `CancelledError` прерывает polling loop без ошибки;
- Двойной `release_slot` обрабатывается идемпотентно;
- Отсутствие `poll_priority_inbound` у канала трактуется как «нет priority-кандидатов».

## Инварианты

- Priority polling выполняется **всегда**, независимо от состояния слотов;
- Обычный polling пропускается, если все слоты заняты;
- `release_slot` идемпотентен (защита от двойного release);
- Каждый in-flight ключ добавляется перед обработкой и удаляется после.

## Запрещённое поведение

Компонент НЕ ДОЛЖЕН:
- зависеть от конкретной реализации транспорта (SQL/Redis);
- блокировать polling loop на обработке одного сообщения;
- позволять обычному polling захватывать слоты при наличии priority;
- создавать несколько polling loop для одного канала;
- хранить сообщения внутри себя (только оркестрация).

## Потребители

- `PostgresChannel` — основной транспорт через SQL-таблицу;
- `RedisChannel` — транспорт через Redis-очереди;
- Тесты — для проверки оркестрации каналов.
