03

12 патчей → 5: что заменяется хуками

Вы были правы, что стоит проверить хуки. Проверил фактическую поверхность nanobot-ai==0.3.5: у AgentHook 18 методов, у AgentHookContext мутабельные поля, и есть 23 события.

Что даёт 0.3.5

Точки, которых не было в прежней редакции.

  • finalize_content(ctx, content) → str | None — вызывается в runner.py трижды, подменяет финальный контент
  • AgentHookContext мутабельный: messages, tool_results, error
  • AgentTurnHookContext.events: EventSink — хук публикует события
  • AgentTurnHookFactory — официальная фабрика per-turn хуков
  • TurnCompleted несёт outcome, failure_kind, failure_error_kind, failure_attempts

Ловушка, которую надо знать

Наличие хука ≠ возможность повлиять.

В execution.py вызов идёт так: result = await tool.execute(...) → await hook.after_execute_tool(context, ..., result) → return result. Хук получает результат, но возвращаемого значения не имеет, а раннер отдаёт result без изменений. Подменить содержимое результата в контексте через хук нельзя.

Отсюда правило: проверять не наличие хука, а наличие у него возвращаемого значения. finalize_content возвращает значение и подменяет контент — работает. after_execute_tool — нет.

04

Порядок работ

Исправлен после аудита: FAISS собирается из снапшота, поэтому `vector-mcp` обязан читать из PostgreSQL раньше, чем снапшот исчезнет.

  1. ШАГ 0

    Принятые удаления: agent_worker_claims с протоколом аренды, benchmarks/, streamlit вместе с subprocess_manager.py, example.py, сломанный и мёртвый код. Каждый набор — отдельный коммит с DROP-миграциями и пересборкой baseline.

  2. ШАГ 1

    libs/data ← workspace/utils/db.py + sql_safety + jsonb + clean_text. Это перенос готового модуля, а не постройка.

  3. ШАГ 2

    data-mcp — тонкая MCP-поверхность над libs/data.

  4. ШАГ 3

    vector-mcp — сборка FAISS напрямую из PostgreSQL. Переносит build_faiss_index, group_vector_hits и векторную половину cache_provider_impl.py.

  5. ШАГ 4

    Удаление DuckDB одним коммитом, без MCP-работы. Векторный поиск к этому моменту уже не зависит от снапшота.

  6. ШАГ 5

    Замена патчей на хуки: turn_delivery_fail и save_turn уходят первыми — у них есть готовые точки расширения. async_save и session_content_cleanup переезжают в PGSessionManager.

  7. ШАГ 6

    Логирование через data-mcp: буфер в агенте, батчевый flush, дроп при переполнении. db_logging_bus.py остаётся в агенте.

  8. ШАГ 7

    libs/document и перенос legal_summarizer — 30 000 строк с нулевой связностью.

  9. ШАГ 8

    audit-analyzer поверх двух серверов. CLI-граница уже существует.
