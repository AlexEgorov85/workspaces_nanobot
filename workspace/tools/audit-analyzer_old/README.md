# Audit Analyzer

Комплексный навык для анализа аудиторских проверок с тремя режимами работы: заготовленные скрипты, генерация SQL и векторный поиск.

## 🎯 Обзор

**Audit Analyzer** - это расширенный навык для анализа результатов аудиторских проверок, который автоматически выбирает оптимальный метод обработки запроса:

### 🔄 Три режима работы

1. **📋 Заготовленные скрипты** - быстрые параметризованные запросы
2. **🔍 Векторный поиск** - семантический поиск по документам
3. **🤖 Генерация SQL** - создание запросов через нейросеть

## 📋 Возможности

### 🎯 Заготовленные скрипты
6 готовых аналитических скриптов с автоматическим извлечением параметров:

| Скрипт | Описание | Пример запроса |
|--------|----------|----------------|
| `analytics_by_year_month` | Аналитика по годам/месяцам | "покажи статистику за 2024 год" |
| `violations_by_type` | Нарушения по типам | "статистика нарушений по категориям" |
| `top_audited_objects` | Топ проверяемых объектов | "топ 10 объектов по проверкам" |
| `audit_effectiveness` | Эффективность проверок | "оценка результатов проверок" |
| `audit_dynamics` | Динамика по периодам | "динамика проверок по кварталам" |
| `audit_types_stats` | Статистика по типам | "классификация проверок по типам" |

### 🔍 Векторный поиск
- Семантический поиск по аудиторским документам
- Поиск по содержанию нарушений и рекомендаций
- Интеграция с навыком vector-search

**Примеры запросов:**
- "финансовые нарушения в университетах"
- "кадровые вопросы при проверках"
- "налоговые нарушения за последний год"

### 🤖 Генерация SQL
- Автоматическая генерация SQL через LLM
- Валидация безопасности запросов
- Поддержка сложных аналитических запросов

**Примеры запросов:**
- "найди проверки с наибольшим количеством нарушений"
- "покажи объекты с повторными нарушениями"
- "сравни эффективность разных типов проверок"

## 🏗️ Архитектура

### Логика работы
```
Запрос пользователя
    ↓
1. Поиск заготовленного скрипта (по ключевым словам)
    ↓ (если не найдено)
2. Векторный поиск по документам
    ↓ (если нет результатов)
3. Генерация SQL через LLM
```

### Компоненты
- **DatabaseManager** - работа с PostgreSQL и кэширование
- **PredefinedScripts** - управление заготовленными скриптами
- **AuditVectorSearch** - интеграция с векторным поиском
- **AuditAnalyzerAPI** - основной API с логикой выбора метода

## 📊 Форматы результатов

### Заготовленный скрипт
```json
{
  "status": "executed",
  "method": "predefined_script",
  "sql": "SELECT EXTRACT(YEAR FROM actual_date) as audit_year, ...",
  "script_name": "analytics_by_year_month",
  "parameters": {"year_filter": "AND EXTRACT(YEAR FROM actual_date) = 2024"},
  "execution": {"row_count": 12, "rows": [...]}
}
```

### Векторный поиск
```json
{
  "status": "vector_search",
  "method": "vector_search",
  "results": [
    {
      "content": "Проверка: Финансовая ревизия | Тип: финансовый | ...",
      "score": 0.89,
      "source": "audit_database"
    }
  ],
  "total_found": 5
}
```

### Сгенерированный SQL
```json
{
  "status": "executed",
  "method": "generated_sql",
  "sql": "SELECT a.title, COUNT(v.id) as violation_count FROM ...",
  "explanation": "SQL-запрос сгенерирован нейросетью на основе схемы базы данных",
  "execution": {"row_count": 8, "rows": [...]}
}
```

## 🔧 Требования

- **PostgreSQL** с базой аудиторских проверок
- **Python 3.8+**
- **Библиотеки**: asyncpg, aiohttp
- **Навык vector-search** (для векторного поиска)
- **Доступ к LLM API** (OpenRouter или другой)

## 🚀 Преимущества

1. **Интеллектуальный выбор метода** - автоматическое определение оптимального подхода
2. **Высокая скорость** - заготовленные скрипты выполняются мгновенно
3. **Гибкость** - поддержка сложных запросов через генерацию SQL
4. **Семантический поиск** - поиск по смыслу, а не по ключевым словам
5. **Безопасность** - валидация и ограничения SQL-запросов
6. **Кэширование** - оптимизация повторных запросов к схеме БД
