# 📁 Data Analyzer Skill

Навык для анализа файлов в папке или списке файлов. Поддерживает **ровно два режима работы**:

| Режим | Описание | Когда использовать |
|:------|:---------|:-------------------|
| `llm_text` | Семантический анализ текстов, логов, кода через LLM. Автоматически чанкирует большие файлы (70% контекста), использует retry (до 3 попыток) и итеративно объединяет результаты. | Поиск причин ошибок, саммари, анализ паттернов, работа с `.log`, `.txt`, `.md`, `.py` и другими неструктурированными файлами. |
| `pandas` | Быстрая аналитика табличных данных. Загружает файл → описывает структуру → генерирует Python-скрипт через LLM → выполняет его → возвращает точный ответ. | Подсчеты, группировки, фильтрация, статистика, агрегация по столбцам. Работает с `.csv`, `.xlsx`, `.xls`, `.json`. |

## 📦 Установка
1. Скопируйте папку `data-analyzer` в директорию навыков.
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. При необходимости отредактируйте `config.json` (укажите `api_url`, `context_window` и ключи доступа к LLM).

## ⚙️ Аргументы командной строки
Все параметры передаются напрямую в `analyze.py` через обертки `analyze.bat` / `analyze.sh`.

| Аргумент       | Обязательный | Описание                                      | Значение по умолчанию |
|----------------|:------------:|:----------------------------------------------|:----------------------|
| `--mode`       | ✅ Да        | Режим анализа: `llm_text` или `pandas`        | — |
| `--path`       | ❌ (или `--files`) | Путь к папке для рекурсивного анализа      | — |
| `--files`      | ❌ (или `--path`)  | Список конкретных файлов через пробел     | — |
| `--question`   | ✅ Да        | Текст вопроса для анализа                     | — |
| `--report`     | ❌           | Формат выходного отчета: `md` или `json`      | `md` |
| `--output`     | ❌           | Путь для сохранения отчета в файл             | Вывод в консоль |
| `--ext`        | ❌           | Фильтр по расширениям файлов                  | `.txt .log .csv .json .xlsx` |

## 🚀 Примеры запуска

### Windows (`analyze.bat`)
Скрипт является оберткой и автоматически пробрасывает все переданные параметры в `python scripts/analyze.py %*`.
```bat
:: Режим 1: Анализ лога через LLM (автоматический чанкинг + retry)
analyze.bat --mode llm_text --files server.log --question "Найди все критические ошибки и их временные метки"

:: Режим 2: Аналитика CSV через Python/Pandas
analyze.bat --mode pandas --files sales.csv --question "Посчитай общую выручку по каждому менеджеру"

:: Режим 2: Анализ папки с сохранением отчета
analyze.bat --mode pandas --path ./data --ext .csv .xlsx --question "Сколько уникальных пользователей?" --output report.md
```

### Linux/macOS (`analyze.sh`)
Предварительно дайте права на исполнение: `chmod +x analyze.sh`  
Скрипт пробрасывает аргументы через `python scripts/analyze.py "$@"`.
```bash
# Режим 1: Анализ нескольких текстовых файлов
./analyze.sh --mode llm_text --files log1.txt debug.log --question "Какие API-эндпоинты вызывают 500-е ошибки?"

# Режим 2: Быстрый расчет по Excel-файлу
./analyze.sh --mode pandas --files report.xlsx --question "Выведи топ-5 товаров по продажам за последний месяц"
```

## 💡 Правила выбора режима
1. **Нужны точные цифры/группировки/фильтры?** → `pandas`. LLM не вычисляет, он пишет код. Pandas считает точно.
2. **Нужно понять смысл, найти причинно-следственные связи или просуммировать текст?** → `llm_text`.
3. **Файл > 50 МБ или > 100 000 строк?** → `llm_text` автоматически включит чанкинг. `pandas` загрузит файл целиком (требует достаточно RAM).
4. **Смешанные данные?** → Если структура табличная → `pandas`. Если хаотичный лог/текст → `llm_text`.

## ⚠️ Важно
- `context_window` в `config.json` должен соответствовать вашей модели. От него автоматически рассчитывается размер чанка (70%).
- Режим `pandas` выполняет сгенерированный код в изолированном контексте. Не анализируйте файлы из ненадежных источников.
- При превышении контекста в режиме `llm_text` результаты чанков сливаются итеративно до тех пор, пока итог не уместится в лимит.
- Ошибки чтения файлов или выполнения кода логируются в консоль, процесс не прерывается.
