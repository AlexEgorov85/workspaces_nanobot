# Аудит: проверки, нарушения, отчёты

Данные внутреннего аудита живут на платформе и читаются её операциями.
Навык объясняет, **когда и какую звать**; общий контракт вызовов — в навыке
`enterprise_mcp`, и он обязателен: там личность вызова, конверт ответа,
крупный результат и полный список кодов отказа.

## Выбор операции

| Операция | Что делает | Обязательные аргументы |
|---|---|---|
| `audit.list_scripts` | Показать готовые скрипты: что вообще можно посчитать | |
| `audit.run_script` | Посчитать готовым скриптом по его имени из каталога | `script` |
| `audit.generate_sql` | Ответить на вопрос по данным аудита обычной фразой | `query` |
| `vectors.vector_search` | Семантический поиск: найти по смыслу, а не по точному слову | `query`, `index_name` |
| `vectors.list_indexes` | Показать векторные индексы: имена и состояние каждого | |

Имя операции пишется с capability: `audit.…` и `vectors.…` — разные capability,
и звать операцию другой нельзя. Префикс в имени — часть имени, а не украшение.

Порядок выбора:

1. Вопрос про **конкретную метрику или срез** (сколько, доля, динамика,
   распределение) — `audit.generate_sql`. Это основной путь: фраза переводится в
   запрос платформой, писать SQL руками не нужно и нельзя.
2. Вопрос про **смысловую похожесть** (найди нарушения, похожие на этот текст;
   что писали про эту организацию) — `vectors.vector_search`. Поиск идёт по смыслу,
   поэтому годятся разные формулировки одного и того же. Имя индекса бери из
   `vectors.list_indexes`, не из памяти.
3. Вопрос, на который есть **готовый сценарий** в `audit.list_scripts` —
   `audit.run_script`. Сначала посмотри каталог: имена скриптов оттуда, из памяти
   не бери, несуществующее имя вернёт `not_found`.
4. Не знаешь, что можно спросить, — `audit.list_scripts`.

## Индексы для `vectors.vector_search`

`index_name` — обязательный аргумент, и **имена индексов даёт операция
`vectors.list_indexes`**: она возвращает имена и состояние каждого индекса
(`missing` / `building` / `ready` / `error`) и ничего не строит. Здесь имена
намеренно не перечислены: перечень в навыке — копия объявления платформы, и новый
индекс в нём появился бы только если кто-то догадается отредактировать этот файл.

Указывай `index_name` **всегда**: без него платформа подставит индекс по
умолчанию, которого в объявлении нет, и вернёт пустую выдачу вместо ошибки.
Это самая дорогая ошибка навыка — она выглядит как «ничего не нашлось».

Порядок работы: `vectors.list_indexes` → выбери индекс по смыслу вопроса →
`vectors.vector_search`. Выбор по смыслу: «найди нарушения…» — индекс про нарушения,
«…проверки такой-то организации» — про проверки, «…в отчётах писали про…» — про
отчёты; точные имена смотри в ответе `vectors.list_indexes`. Имя, которого в ответе
не было, не выдумывай: несуществующее имя вернёт `not_found`, и «пусто» будет
выглядеть как отсутствие данных.

## Как читать ответ

- Тело ответа — данные, `_execution` — метаданные вызова. Не пересказывай
  метаданные, если о них не спрашивали.
- Крупный результат не режется молча: в `_execution.artifact` придёт ссылка
  вида `session://results/...`. Это НЕ «ответ обрезан» — прочитай файл через
  `platform.read_result` (см. навык `enterprise_mcp`), иначе вывод будет сделан по
  неполным данным.
- Пустой результат по `vectors.vector_search` — это либо «не нашлось», либо не тот
  индекс. Второе встречается чаще, и выглядит как первый.

## Отказы: что делать

| Код | Реакция |
|---|---|
| `invalid_params` | Сверься со схемой операции и исправь аргумент |
| `not_found` | Имя скрипта или индекса не существует; возьми его из каталога |
| `no_match` | Данных по запросу нет — это результат, скажи пользователю |
| `not_answerable` | Вопрос нельзя построить по доступным данным; сузь или переформулируй |
| `timeout` | Повтори с более узким запросом: сократи период или срез |
| `index_build_failed` | Индекс не собрался; это инфраструктура, не твой запрос |
| `upstream_unavailable` | Нет доступа к данным; инфраструктура, повтор позже |

Полный список кодов и признак `retryable` — в навыке `enterprise_mcp`.

## Правила

- **Не пиши SQL.** Операции принимают вопрос фразой; проверку запроса
  платформа делает сама, и обход этого пути лишает вызов изоляции и журнала.
- **Не выдумывай имена** скриптов, индексов, полей и операций: бери их из
  `audit.list_scripts` и `vectors.list_indexes`, а имя операции — из белого
  списка в навыке `enterprise_mcp`.
- **Не повторяй отказ с теми же аргументами**, если `retryable` не выставлен.
- **Не смешивай операции в один вызов.** На каждый вопрос — свой вызов; если
  вопросов несколько, спроси у пользователя, с какого начать.
- **Не вызывай инфраструктурные операции** платформы (журнал, очередь,
  сообщения). Это не доменный навык: таких инструментов в твоём списке нет.
