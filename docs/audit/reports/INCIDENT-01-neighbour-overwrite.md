# Инцидент: перезапись незакоммиченной работы соседнего воркера

**Дата:** 2026-10-03 · **Ветка:** `refactor/mcp-platform` · **HEAD:** `9223ae2`

## Что произошло

Я готовил изолированный worktree, чтобы прогнать набор тестов на дереве
«HEAD + только мои правки» и не захватить правки соседнего воркера. Для
этого написал скрипт сплайса (`_tmp_build_isolated.py`), который берёт версию
файла из HEAD и накладывает мои изменения как точные строковые замены.

В скрипте цель задавалась так:

```python
ROOT = pathlib.Path(__file__).resolve().parents[3]   # ← путь САМОГО скрипта
```

Скрипт лежит в `docs/audit/_scripts/` **основного** репозитория, поэтому
`parents[3]` указывал на основной репозиторий, а не на worktree.

**Последствия:**

- изолированный worktree остался нетронутым — проверка не состоялась;
- 14 файлов основного дерева были перезаписаны на «HEAD + мои правки»;
- незакоммиченная работа соседнего воркера в этих файлах **уничтожена**.

Индекс при этом был и остаётся пустым (`git diff --cached` пуст), ничего не
закоммичено и не запушено.

## Что именно было потеряно

Состояние зафиксировано ДО перезаписи — по диффам, которые я снял при

## Что сделано после

1. **Сообщение соседней сессии** (`mvs_667ddf11ec6e4a3c8ec1aab182a8e548`,
   «Логирование») отправлено: перечислены файлы, потерянные хунки, и
   отдельно указано, какие правки в этих файлах мои и могут остаться.
2. **Скрипт переписан**: цель берётся только из аргумента командной строки,
   а при попытке указать путь внутри основного репозитория скрипт
   **отказывается работать**. Обе защиты проверены исполнением.
3. **Правило записано в память агента** — скрипту, пишущему файлы, запрещено
   выбирать цель по расположению собственного файла.

## Почему не восстановлено «по памяти»

Диффы `gateway.py` и `application_context.py` я видел только в виде
заголовков хунков (`@@ …`), без содержимого. Восстанавливать по догадке
значило бы записать в чужие файлы вымысел и накрыть реальную работу
вторым слоем неверных правок. У соседа есть исходный текст в его контексте —
это надёжнее любой реконструкции.
