# Аудит: dev-утилиты (`tools/`, `scripts/`) — группа E

Разбирал лично родительский агент (слот воркера не освободился из-за лимита
конкурентности 4). Формат — по `docs/audit/AUDIT_PROTOCOL.md`.

## Сводка группы

Файлов: 10 (+ 2 PowerShell-скрипта, вне AST-скоупа) · LOC: ~2900

**Важное замечание по методу.** `tools/` — standalone-скрипты, запускаемые
вручную из CLI. У них по определению нет импортёров, поэтому «0 импортёров»
не является доказательством мёртвости (прямо сказано в протоколе, п. 1).
Оценка велась по трём другим основаниям: работает ли скрипт, соответствует ли
он текущей архитектуре, дублирует ли он что-то ещё.

**Ключевые находки**

- `tools/legacy_audit.py` (486 LOC) — **остаток снятой подсистемы.** Весь
  реестр запрещённых символов/файлов состоит из модулей `legal_summarizer`,
  каталога которого в репозитории больше нет. Импортирующих нет ни в агенте,
  ни в платформе.
- `tools/cleanup_tombstone_tests.ps1` — одноразовый уборщик, чей
  защитный список и `.DESCRIPTION` ссылаются на `tests/benchmarks/`,
  `mcp-platform/tests/legal_summarizer/…` и `tools/apply_test_profile_tables.py`.
  Часть защищаемого уже не существует.
- `tools/validate_component_specs.py` — **жив и работает**, но падает:
  exit 1, 7 нарушений, все в одном файле `openspec/specs/logging-db/spec.md`.
- `_bak_*`/`_mut*`-черновики из `OPEN-WORK.md` п. 4 **уже удалены** соседним
  воркером — пункт устарел (проверено `Test-Path` и `git status`).

## `tools/legacy_audit.py` — 486 LOC

**Назначение.** Регрессионный страж: AST-скан по репозиторию, который ищет
импорты удалённых legacy-модулей и наличие запрещённых файлов на диске.

**Что делает.** `audit()` обходит все `*.py` от `Path.cwd()`, разбирает их
через `ast` и собирает попадания по `_FORBIDDEN_MODULES`, `_FORBIDDEN_SYMBOLS`.
`assert_no_legacy()` добавляет проверку существования 26 файлов из
`_FORBIDDEN_FILES`, проверку ключа `gateway.vector_index` в `config.json`
и фильтрацию test-хитов по `_ALLOWED_LEGACY_TESTS`. `main()` печатает отчёт.

**Зачем нужен.** Изначально — страж на удаление `legal_summarizer`.

**Вердикт.** `Удалить`.

**Обоснование.** Скилл `legal_summarizer` уехал на платформу (фаза 11), и его
каталога в репозитории нет вообще — проверено `Test-Path`. Из этого следует:

1. `_FORBIDDEN_MODULES` (`:47-67`) — 21 модуль, все с префиксом
   `workspace.skills.legal_summarizer.scripts.`
2. `_FORBIDDEN_FILES` (`:90-117`) — 26 путей, все под
   `workspace/skills/legal_summarizer/scripts/`
3. `_FORBIDDEN_SYMBOLS` (`:70-87`) — 16 символов (`SectionTree`,
   `DocumentSection`, `StructureAwareChunker`, …), ни один из которых не может
   встретиться в коде, где скилла нет
4. `_ALLOWED_LEGACY_TESTS` (`:133-199`) — ~40 записей на два тест-файла,
   которых не существует: `tests/test_legal_summarizer_no_legacy.py` и
   `tests/test_skill_legal_summarizer_characterization.py` (проверено —
   оба `False`)

То есть страж охраняет от возврата кода, которого в проекте нет. Он не ловит
ничего: любой новый legacy-импорт в `legal_summarizer` невозможен, потому что
каталога нет.

**Доказательства.** Потребителей нет: `git ls-files` даёт единственное
совпадение — сам файл плюс `mcp-platform/tests/legal_summarizer/test_legacy_audit.py`,
но этот тест **не импортирует** `tools/legacy_audit.py` (он проверяет своё,
через `Path(__file__).parents[2]`); grep по `import` в нём даёт только `pathlib`.
Теста самого `tools/legacy_audit.py` в `tests/` нет. Импорт модуля проверен
исполнением: проходит без ошибок, публичный API
`{assert_no_legacy, audit, audit_legacy_in_module, main}`.

**Что сделать перед удалением.** Файл не удаляется, а заменяется: если нужен
общий страж «ничего не ссылается на снятое», его содержание должно быть
переписано на актуальный реестр (например, модули `duckdb_cache_store`,
`cache_provider`, `legal_summarizer`). Текущие `tests/test_no_cache_api_remains.py`
и `tests/test_llm_goes_through_mcp.py` эту роль уже выполняют для снятого
кэш-кластера — то есть защита не пропадёт вместе с файлом.

## `tools/migrate.py` — 252 LOC

**Назначение.** Runner миграций схемы по файлам `sql/migrations/V*.sql`.

**Что делает.** Читает `config.get_setting` для DSN, сортирует версии по
номеру в имени, ведёт учёт в `public.schema_migrations` вместе с SHA256
содержимого. Повторное применение пропускает, изменение уже применённого
файла считает drift-ошибкой. Режимы: `--status`, `--dry-run`, `--apply`,
`--target`, `--baseline`, `--verify`.

**Зачем нужен.** Единственный способ применить миграции схемы; в репозитории
есть `sql/migrations/V001…V009`, включая незакоммиченные `V008`/`V009`
(журнал: индексы по времени событий).

**Вердикт.** `Оставить`.

**Обоснование.** Регламентная роль, привязана к живым артефактам репозитория.
Контрольные суммы — то, что обычный `psql -f` не даёт.

**Доказательства.** Покрыт `tests/test_migrations.py` (106 LOC) — единственная
утилита `tools/` с тестом. Импортирует `config.get_setting` — живой модуль.

**Примечание.** Docstring (`:17-18`) говорит «ключ `channels.postgres.dsn`
из project.json», тогда как файл конфигурации в проекте — `config.json`
(см. `tools/legacy_audit.py:365-368`, где это уже исправлено). Строка вводит
в заблуждение — мелкая правка.

## `tools/run_tests.py` — 738 LOC

**Назначение.** Планировщик прогона pytest под жёстким потолком памяти.

**Что делает.** Вешает ограничение памяти ОС на всё дерево процессов прогона
(включая дочерние `enterprise-mcp`), плюс предел времени. Коды возврата
`0-5` — код pytest пройден как есть, `120` — сработал потолок памяти,
`121` — ограничение построить не удалось и прогон не состоялся. Подключает
третий слой — плагин `tests/_memguard.py`.

**Зачем нужен.** Наблюдался прогон, раздувшийся до 3.5–9.2 ГБ на машине
с 16 ГБ (свободная память падала до 455 МБ). Локализовать утечку не удалось,
поэтому сделан барьер, работающий всегда.

**Вердикт.** `Оставить`.

**Обоснование.** Решает реальную, не локализованную проблему. Важна деталь
кода возврата `121`: молча пропустить барьер нельзя, «барьер, который не
включился, хуже, чем его отсутствие» — редкая и правильная формулировка
в этом репозитории.

**Доказательства.** Упоминается в `docs/TESTING.md`; сам `_memguard.py` (199 LOC)
лежит в `tests/`. Умеет гонять обе кодовые базы (`--root mcp-platform`),
что делает его общим инструментом проекта.

## `tools/diagnose_startup.py` — 451 LOC

**Назначение.** Парсит startup-лог gateway/CLI и сверяет зарегистрированные
хуки, project-tools и рантайм-патчи с каноном из `runtime_inventory`.

сохранённому логу, что всё зарегистрировалось. Есть машинный режим
(`--json`) для CI.

**Вердикт.** `Оставить`.

**Обоснование.** Проверен в работе: `--help` отрабатывает, exit 0, все флаги
на месте (`--log`, `--strict`, `--no-color`, `--json`).

**Доказательства.** Покрыт `tests/test_diagnose_startup.py` (179 LOC). Импортирует
канон из `lib/services/runtime_inventory.py`, поэтому расхождение с ним
проверяется тестом, а не вручную.

**Проверенная связка.** Историческая находка D-4 (ложный DRIFT из-за

## `scripts/backfill_media_aw.py` — 125 LOC

**Назначение.** Однократный перевод исторических медиа в формат AW
(`audit_point_new`).

**Что делает.** Переписывает в `agent_conversation_messages.media` только

**Обоснование.** Скрипт идемпотентен и безопасен; пока миграция формата не
выполнена на всём объёме, он нужен. После завершения — разовая операция,

**Доказательства.** Переиспользует живой `workspace/utils/media.py`

## `tools/cleanup_scratch.ps1` — PowerShell, 10.9 KB (вне AST-скоупа)

**Назначение.** Уборка одноразовых артефактов репозитория.

**Что делает.** Удаляет **только** заранее проверенный список путей; glob-удаления
нет намеренно, потому что в репозиторий параллельно пишет другой агент.
Без `-Apply` только показывает план. Отказывается удалять путь, если он
оказался под git, — значит список устарел. `-IncludePycache` дополнительно
сносит `__pycache__`.

**Вердикт.** `Оставить`.

**Обоснование.** Обоснованный отказ от шаблонов — в этом репозитории
удаление опасно именно из-за параллельной работы, и скрипт это учитывает
(«шаблон вида `*.tmp` однажды снёс бы чужой файл молча, и это невосстановимо»).

**Примечание.** `PENDING-DELETIONS.md` утверждает, что удаление файлов в этой
среде заблокировано политикой. Скрипт с этим не согласуется и при `-Apply`
удалит. Это не дефект самого скрипта, но повод держать его в известном
состоянии.

## `tools/cleanup_tombstone_tests.ps1` — PowerShell, 6.7 KB (вне AST-скоупа)

для этого файла**. Каталоги удаляются через `rmdir` без рекурсии.

**Вердикт.** `Удалить`.

**Обоснование.** Одноразовый инструмент, чья работа уже выполнена

пакетный каркас»), и который теперь вводит в заблуждение:

1. `.DESCRIPTION` (`:22`) защищает `tests/benchmarks/_conftest.py` — каталога
   `benchmarks/` в репозитории нет
2. Там же (`:23-24`) защищает `mcp-platform/tests/legal_summarizer/fixtures/…`
   — этой структуры больше нет (проверено `Test-Path`; каталог
   `mcp-platform/tests/legal_summarizer/` существует, но `fixtures/analysis_cases/`
   в нём нет)
3. `.EXAMPLE` (`:32-33`) предлагает PowerShell-команду, тогда как проект
   работает в основном под `python tools/…`

Скрипт не вредит (он ничего не удаляет без `-Apply`), но хранит
несуществующие пути как «защищённые» — то есть создаёт ложное впечатление
покрытия.

**Доказательства.** `git log` — `592f1e2`; защищаемые пути отсутствуют,
проверено `Test-Path`.
